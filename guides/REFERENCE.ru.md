# Настройка и техническая справка

> Справка описывает выпущенную 0.5.1. Архитектура компонентов и штатное сжатие версии 0.6.0 описаны в [Native provider integration](NATIVE-PROVIDER.md). В версии 0.6.0 переполнение обычного запроса передаётся компакту Harness; внутренние резюме по частям используются только для вспомогательных запросов.

[← К обзору проекта](../README.ru.md)

Выбор модели, восстановление диалога, учёт расхода, границы инструментов и проверки для v0.5.1.

## Выбор модели

Выберите провайдера **OpenAI Codex (ChatGPT OAuth)** и модель в интерфейсе Harness. Список берётся из Codex, а не задан в коде плагина. Наличие модели в каталоге само по себе не гарантирует доступ к ней на вашем аккаунте.

Пример настройки в `~/.dsh/profiles/web/cordis.patch.yml`:

```yaml
- id: agent-default-model
  config:
    provider: openai-codex
    model: gpt-6.1-sol
    reasoningEffort: high
```

Укажите идентификатор модели, доступной в вашем списке. Обычный запуск без веб-интерфейса:

```sh
npx @deepseek-ai/dsh --profile headless "изучи этот репозиторий"
```

## Рабочая папка сессии

При создании нового чата Codex плагин читает рабочую папку из метаданных соответствующей сессии Harness. Разные сессии могут работать в разных каталогах. Если метаданных каталога нет либо запрос выполняется вне сессии, используется каталог процесса плагина.

**После обновления начните новую сессию Harness:** уже созданные чаты Codex сохраняют прежний каталог.

## Проценты лимитов ChatGPT

Рядом со штатной статистикой шагов/токенов под полем ввода показываются реальные проценты лимитов — каждое сообщённое сервером окно отдельной строкой. Выводится **использованный** процент и фактическая длительность окна; время сброса доступно в подсказке. Данные читаются через Codex `account/rateLimits/read` раз в 30 секунд, пока страница видима. Отсутствующие окна не выдумываются; недоступность показывается явно. Это лимиты аккаунта, отдельно от счётчиков токенов. Поддержаны русский, английский и китайский языки интерфейса.

## Расход токенов (usage)

Адаптер передаёт счётчики `thread/tokenUsage/updated` из Codex в Harness. В подробном режиме статистики штатный индикатор токенов появляется рядом с числом ходов/шагов; по нажатию видны вход без кэша, чтение/запись кэша и выход. В компактном режиме показывается процент попаданий в кэш. Reasoning-токены входят в выход и не прибавляются к нему второй раз.

Накопительные счётчики потока Codex преобразуются в приращения по вызовам Harness, включая паузы на инструменты: повторные уведомления не задваивают расход. Отсутствующие, некорректные или уменьшившиеся счётчики не оцениваются на глаз. Пропущенный старыми версиями расход задним числом не восстанавливается. Это учёт токенов, не лимиты подписки ChatGPT и не стоимость в долларах. После обновления активного провайдера нужен перезапуск Harness.

Offline-проверка с установленным Harness, без credentials и вызовов модели:

```sh
DSH_RUNTIME_ROOT=/путь/к/node_modules/@deepseek-ai node scripts/harness-usage-smoke.mjs
```

## Разрешения инструментов

Доступ к файлам и подтверждения для динамических инструментов контролирует Harness. Встроенные инструменты среды Codex отключены через `environments: []`, а его собственная песочница остаётся в режиме чтения. Эти ограничения Codex не подменяют политику инструментов, выполняемых Harness.

Адаптер передаёт модели фактические результаты инструментов, включая отказ в доступе. Отказ Harness не превращается в успешное выполнение.

## Восстановление контекста и сжатие

История Harness — источник истины. После рестарта/HMR адаптер возобновляет завершённый Codex thread, сверяя отпечаток истории, ответ ассистента, сессию, настройки и последний сохранённый turn. Учёт расхода продолжается с сохранённых счётчиков. Старые, несовместимые и незавершённые checkpoints требуют восстановления из текущей истории, включая результаты инструментов. Изменение истории также пересоздаёт диалог, если нет ожидающих ответов инструментам; смена системных инструкций, модели или инструментов пересоздаёт его и во время паузы на инструмент. Восстановление использует текстовую запись с обозначением ролей; старые вызовы инструментов повторно не исполняются.

`/compact` и генерация заголовка изолированы в отдельных временных текстовых диалогах без инструментов. `maxTokens` для них — **мягкая инструкция**, а не гарантированный сервером потолок: Codex app-server не предоставляет такого параметра. Для обычного диалога явные maxTokens/temperature/stop по-прежнему отклоняются. После сжатия основной диалог использует новую историю Harness.

Большие входы (более 200 000 UTF-16 символов) предварительно сжимаются: старые данные обрабатываются по частям в изолированных диалогах без инструментов; последние 60 000 символов остаются дословными. Это смысловое резюме, не побайтовое восстановление; исходный журнал Harness не изменяется. Все старые фрагменты участвуют в сжатии, при необходимости — в несколько уровней. Если резюме пустое, слишком большое или запрос отменён, операция завершается явно, без молчаливого обрезания. Лимит Codex относится к сумме частей запроса, поэтому простое разбиение массива его не обходит. Дополнительные вызовы сжатия расходуют токены, которые включаются в usage. Большое восстановление может занять время; после рестарта может потребоваться повторное сжатие.

Новые текстовые указания, включая сообщения субагентов, передаются через `turn/steer` до ответа инструменту. Thread сохраняется, повторный пересказ старой истории не запускается. Ошибка steering завершается явно; настоящая замена истории по-прежнему пересоздаёт thread. При `willRetry` адаптер ждёт результата штатной повторной попытки Codex. Изменённый в истории ответ ассистента проверяется на соответствие ранее сгенерированному. После завершения процесса Codex ожидающие и будущие чтения его очередей получают ошибку, а устаревшие вызовы инструментов не выдаются как успешные.

Ошибки отправки/прерывания сбрасывают состояние адаптера: повтор строится из сохранённой истории, а не из незавершённого потока. Временные диалоги сжатия освобождаются. Изменение модели/инструкций/инструментов во время паузы на инструмент также пересоздаёт поток из истории, не переисполняя старые вызовы.

Проверка на реальной модели (использует существующий вход ChatGPT):

```sh
DSH_HISTORY_SMOKE_MODEL=gpt-6.1-sol node scripts/history-smoke.mjs
```

Нажмите строку лимита: раскроются использованный/оставшийся процент, длительность окна, дата сброса и обратный отсчёт, время получения и кнопка обновления. Лимиты не являются счётчиком токенов; отсутствующие окна не выдумываются.

## Нативный веб-поиск Codex

Плагин регистрирует провайдер `openai-codex` в штатном сервисе `web` Harness. Поиск использует вход ChatGPT и нативный live web search Codex в отдельном временном диалоге; ключ DeepSeek не нужен. Обычный инструмент `web_search` сохраняет карточки источников, метаданные в истории и ссылки Markdown. Используется модель текущего диалога Codex, а вне него — модель по умолчанию из каталога Codex.

Выбор в патче профиля:

```yaml
- id: web
  config:
    searchProvider: openai-codex
    fetchProvider: openai-codex
- id: tool-web
  config:
    searchTimeoutMs: 120000
    fetchTimeoutMs: 120000
```

Регистрация сама по себе не переключает существующий поиск. Встроенный переключатель настроек DeepSeek по-прежнему выбирает его провайдеры и может заменить этот выбор. Поиск расходует квоту ChatGPT; модель и расход записываются в события `plugin:dsh-openai-oauth/search-llm-request`. Если Codex не выполнил нативный поиск, ответ отклоняется. Заголовки и описания формируются по результатам поиска; URL проверяются и дедуплицируются, даты публикации не выдумываются. Отмена прерывает и освобождает временный thread. В основных диалогах, заголовках и компактизации нативный поиск остаётся выключенным.

Живые проверки: `node scripts/web-search-smoke.mjs` и `DSH_CLI=/path/to/dsh/lib/bin.js node scripts/harness-web-search-smoke.mjs`.

Провайдер также поддерживает `web_fetch` через нативный Codex `openPage`. Он возвращает извлечённый моделью текст, а не исходный HTML; полнота и дословность не гарантируются. HTTP-код app-server не сообщает: значение `0` означает «неизвестен», что явно поясняется в результате. Ответ без подтверждённого открытия запрошенного URL и читаемого результата отклоняется. Использование токенов записывается в `plugin:dsh-openai-oauth/fetch-llm-request`. Для обычного HTTP-транспорта можно оставить `fetchProvider: http`. Проверка: `DSH_CLI=/path/to/dsh/lib/bin.js node scripts/harness-web-fetch-smoke.mjs`.

## Изображения

Вложения пользователя и картинки из результатов MCP-инструментов передаются в Codex как изображения через хранилище вложений Harness. Поддерживаются PNG, JPEG, WebP и GIF; текст и картинки в смешанных результатах сохраняются. При восстановлении истории изображения привязываются к исходным сообщениям, а выгруженные изображения не загружаются повторно. Байты изображений не включаются в текстовые резюме.

Живая проверка: `DSH_CLI=/path/to/dsh/lib/bin.js node scripts/harness-images-smoke.mjs /absolute/screenshot.png "видимый текст"`. Она проверяет полный путь MCP → вложение Harness → распознавание Codex.

## Генерация и редактирование изображений

`image_generate` создаёт одну картинку через нативный Codex image generation с текущим входом ChatGPT. `image_edit` принимает инструкцию и от одного до четырёх `image_ids` — идентификаторов активных вложений текущего чата. Для локального файла сначала используйте штатный `read_image`. Исходники передаются нативными изображениями непосредственно в контекст отдельного вызова; генератор редактирует их через `num_last_images_to_include`, без доступа к локальным путям. Исходные вложения не изменяются.

Оба инструмента возвращают новое PNG-вложение Harness, сохраняемое до записи результата инструмента. Параметр `transparent_background` необязателен; при редактировании без него модель получает указание сохранять существующую прозрачность. Изображения обрабатываются в отдельном временном Codex thread без shell, веба и динамических инструментов. Временные копии входных файлов не создаются. Отмена прерывает thread, лимит вызова — 5 минут. Обычный диалог по-прежнему не получает прямого доступа к нативному генератору.

Доступность проверяется через `modelProvider/capabilities/read`. Генерация расходует квоту ChatGPT; наблюдаемый token usage записывается в `plugin:dsh-openai-oauth/image-llm-request` и не подменяет отдельные лимиты генерации. Закреплённая версия CLI возвращает PNG в `result`; ответы только с `fileId` без байтов пока отклоняются явно.

Проверка полного пути генерации и редактирования: `DSH_CLI=/path/to/dsh/lib/bin.js node scripts/harness-image-generation-smoke.mjs`.

Инструменты возвращают также `path`, если путь из нативного результата лежит внутри каталога сгенерированных картинок Codex и файл побайтово совпадает с результатом генерации. Это путь для показа: модель должна сразу вставить `![описание](<path>)` в итоговый ответ и при доступном `present` приложить этот файл. `attachmentId` нужен для последующего редактирования, а не для поиска файла; поиск по приватным каталогам, пересчёт хешей и повторная генерация ради показа не требуются. Для этих инструментов не нужен отдельный навык `imagegen`. Проверка доставки в один ход: `DSH_CLI=/path/to/dsh/lib/bin.js node scripts/harness-image-delivery-smoke.mjs`.

## Удаление

Удалите пакет из нужного профиля:

```sh
dsh plugin --profile web remove dsh-openai-oauth
```

Уберите `dsh-openai-oauth` из списка bundle этого профиля, если запись осталась, и перезапустите Harness. Повторите для других профилей, куда вы устанавливали плагин. Удаление пакета не удаляет сохранённый вход ChatGPT; при необходимости сначала выйдите через **Sign out** в настройках плагина.

## Разработка

```sh
npm install --legacy-peer-deps
npm run build
npm pack --dry-run
```

Переменная `DSH_CODEX_CLI` позволяет указать явный путь к JavaScript-файлу запуска Codex. По умолчанию используется закреплённая зависимость плагина.
